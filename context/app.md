`HypercubeApp` holds only UI-control state (scale/gap sliders, render mode, settings, the reveal toggle's runtime state). Builds a left control panel plus a right `Shader::new(HypercubeShaderProgram)` viewport, with a File/Puzzle/View/Help menu bar (`menu_overlay::bar`, see `menu_overlay.md`/`menu_common.md`) above them. Contains no 3D/4D logic. The sticker-scale/face-gap sliders are hidden behind a "Reveal"/"Hide" toggle button, now on the Puzzle menu: pressing it bumps a `reveal_generation` counter (same one-shot generation-counter pattern `reset_generation` uses to reach `HypercubeShaderState`) and flips `revealed` immediately, while `reveal_animating` disables the button and hides the sliders until `shader_widget.rs` publishes `Message::RevealAnimationComplete` back once the flourish settles.

The Puzzle menu's "1/2/3 Random Moves" and "Scramble" items all send `Message::RandomMoves(count)`, which bumps `random_moves_generation` and stores `count` in `pending_random_move_count` - a payload carried alongside the counter the same way `revealed` accompanies `reveal_generation`, since a bare generation bump can't carry data on its own.

The Puzzle menu's "Reset" item sends `Message::Reset`, which bumps `reset_generation`; re-triggering Reset/Random Moves/Scramble while a previous one is still animating is harmless, since both handlers in `shader_widget.rs` just restart cleanly from whatever the live state is. Spacer rows between the Reset/Random-Moves-and-Scramble/Reveal groups (`menu_common::puzzle_items`) target `Message::NoOp` - `overlay::menu::Menu` has no separator concept, so these are inert rows used purely for visual grouping.

`HypercubeApp` owns all `puzzle_state.rs` I/O; `shader_widget.rs` never touches disk. The File menu's Save item sends `Message::SavePuzzle`, bumping `save_generation` (threaded into `HypercubeShaderProgram::new(...)` alongside the other generation counters); `shader_widget.rs` detects the mismatch, clones its live `Hypercube`, and publishes it back as `Message::PuzzleReadyToSave`, which `HypercubeApp` persists via `puzzle_state::save`. Load sends `Message::LoadPuzzle`, which calls `puzzle_state::load()` synchronously and stores the result in `pending_load: Option<Hypercube>`, threaded into the shader program alongside `load_generation` for it to apply on a mismatch. Quit sends `Message::Quit`, returning `iced::exit()`. `about_open` shows a Help modal, always layered via a constant-shape 2-element `iced::widget::stack` (an inert `Space` placeholder when closed) rather than conditionally wrapping the content in a `stack` - switching the tree root's shape on toggle would otherwise reset every descendant's widget-tree `State`, including the `Shader` widget's generation counters, causing spurious replays (e.g. the reveal flourish firing again) on every open/close. `subscription()` wires Ctrl+Q/Ctrl+S/Ctrl+O/F1 to Quit/SavePuzzle/LoadPuzzle/OpenAbout, mirroring the File/Help menu items.
