`HypercubeApp` holds only UI-control state (scale/gap sliders, render mode, settings, the reveal toggle's runtime state). Builds a left control panel plus a right `Shader::new(HypercubeShaderProgram)` viewport, with a File/Puzzle/View/Help menu bar (`menu_overlay::bar`, see `menu_overlay.md`/`menu_layout.md`) above them. Contains no 3D/4D logic. The sticker-scale/face-gap sliders sit behind a "Reveal"/"Hide" toggle button, now on the Puzzle menu: pressing it bumps a `reveal_generation` counter (same one-shot generation-counter pattern `reset_generation` uses to reach `HypercubeShaderState`), flips `revealed` immediately, sets `reveal_animating` (disabling the button and manual slider interaction until `shader_widget.rs` publishes `Message::RevealAnimationComplete` once the flourish settles), and records `reveal_animation_started`. While `reveal_animating` is true, a `window::frames()` subscription (see `HypercubeApp::subscription`) feeds `Message::RevealAnimationTick` on every redraw, and `app.rs` interpolates `sticker_scale`/`face_gap` itself (via `crate::animation::ease` and the same `PRIMARY_*`/`SECONDARY_*`/`REVEAL_ANIMATION_DURATION` constants `shader_widget.rs` targets) so the slider thumbs visibly track the 3D flourish - this is a separate, independently-timed interpolation from the shader widget's own `AnimatingReveal`, not values threaded out of it.

The sticker-scale/face-gap panel itself (a `Scrollable` with a hidden scrollbar, wrapping a `mouse_area` that swallows its own wheel-scroll input) is always present in the layout, grouped with the Reveal button and the Animation Duration row into one `spacing(0)` sub-column so no gap is ever inserted or removed around it. Its own leading/trailing blank `Space` margins (`SLIDERS_PANEL_GAP`) stand in for that spacing instead. `reveal_panel_fraction` (updated alongside `sticker_scale`/`face_gap` in the same tick handler, via `panel_progress`'s own faster open/close window) drives the panel's height, linearly interpolated between `SLIDERS_PANEL_CLOSED_HEIGHT` (just the leading margin, reading as one ordinary gap) and `SLIDERS_PANEL_OPEN_HEIGHT` (both margins, both rows, and the gap between them) - `Scrollable` gives its content unconstrained height to lay out against regardless of its own configured height, so the rows never reflow, only the visible window clips.

The Puzzle menu's "1/2/3 Random Moves" and "Scramble" items all send `Message::RandomMoves(count)`, which bumps `random_moves_generation` and stores `count` in `pending_random_move_count` - a payload carried alongside the counter the same way `revealed` accompanies `reveal_generation`, since a bare generation bump can't carry data on its own.

The Puzzle menu's "Reset" item sends `Message::Reset`, which bumps `reset_generation`; re-triggering Reset/Random Moves/Scramble while a previous one is still animating is harmless, since both handlers in `shader_widget.rs` just restart cleanly from whatever the live state is. Spacer rows between the Reset/Random-Moves-and-Scramble/Reveal groups (`menu_layout::puzzle_items`) target `Message::NoOp` - `overlay::menu::Menu` has no separator concept, so these are inert rows used purely for visual grouping.

`HypercubeApp` owns all `puzzle_state.rs` I/O; `shader_widget.rs` never touches disk. The File menu's Save item sends `Message::SavePuzzle`, bumping `save_generation` (threaded into `HypercubeShaderProgram::new(...)` alongside the other generation counters); `shader_widget.rs` detects the mismatch, clones its live `Hypercube`, and publishes it back as `Message::PuzzleReadyToSave`, which `HypercubeApp` persists via `puzzle_state::save`. Load sends `Message::LoadPuzzle`, which calls `puzzle_state::load()` synchronously and stores the result in `pending_load: Option<Hypercube>`, threaded into the shader program alongside `load_generation` for it to apply on a mismatch. Quit sends `Message::Quit`, returning `iced::exit()`. `about_open` shows a Help modal, always layered via a constant-shape 3-element `iced::widget::stack` (an inert `Space` placeholder when closed) rather than conditionally wrapping the content in a `stack` - switching the tree root's shape on toggle would otherwise reset every descendant's widget-tree `State`, including the `Shader` widget's generation counters, causing spurious replays (e.g. the reveal flourish firing again) on every open/close. `subscription()` wires Ctrl+Q/Ctrl+S/Ctrl+O/F1 to Quit/SavePuzzle/LoadPuzzle/OpenAbout, mirroring the File/Help menu items.

The stack's third layer is a debug-only FPS counter: while `debug_mode` is on, `subscription()` adds a `window::frames()` subscription mapped to `Message::FpsTick`, and each tick updates `fps` (an exponential moving average over the delta from `last_fps_frame`, reset whenever `debug_mode` is (re-)enabled so a stale timestamp gap can't produce one bogus reading). `view()` renders `fps` as plain `iced::widget::text`, right/top-aligned over the viewport with no `mouse_area`/`opaque` wrapping (unlike the About modal) so it never intercepts clicks meant for the cube underneath - an inert `Space` swaps in for this layer whenever `debug_mode` is off.
