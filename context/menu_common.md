# menu_common.rs

Content and layout constants for `menu_overlay.rs`'s `MenuBar` widget, kept separate so the label/action pairing for each top-level menu lives away from the low-level widget code. `TopMenu` (File/Puzzle/View/Help) is the one enum involved. `MenuItem` pairs a label with the `Message` it sends and a `selected` flag (checkmarked for the current Render Mode/AABB Mode); it implements `Display`/`Clone` specifically so it can be used directly as `overlay::menu::Menu`'s `T: ToString + Clone` option type. `items_for(top, render_mode, aabb_mode, revealed, reveal_animating)` is the single place the File/Puzzle/View/Help item lists are defined: File is Save/Load/Quit; Puzzle is Reset/1-2-3 Random Moves/Scramble/Reveal-or-Hide (the last built via `app::reveal_button_label`, reused rather than duplicated), with blank `spacer_item()` rows (target `Message::NoOp`) between the Reset/Random-Moves-and-Scramble/Reveal groups since `overlay::menu::Menu` has no real separator concept - these rows still highlight on hover and are clickable, they just do nothing; View is Render Mode/AABB Mode; Help is About.
