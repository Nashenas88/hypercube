# solver/

A solver ported from Don Hatch's `NdSolve.java` (Magic Cube 4D, by Melinda Green & Don Hatch - http://superliminal.com/cube/cube.htm; credited in `solver/mod.rs`'s module doc and the Help → About dialog). `solve(&Hypercube) -> Result<Solution, SolveError>` returns a list of native `moves::Move`s, each labelled with the `Stage` it came from, which `shader_widget.rs` plays back (see `shader_widget.md`). `solver/mod.rs`'s module doc explains the algorithm; in short: pieces are grouped by sticker count (2, 3, 4), and each group, smallest first, is positioned (3-cycles, each done as setup + fixed recipe + undo) then oriented (flip pairs, or opposite twirl pairs for corners, each done as flatten + recipe + unflatten), never disturbing a group already done. An odd state first gets one arbitrary quarter turn (`PARITY_TWIST`).

Every Rust function maps to one Java function (named the same, snake-cased), across one file per Java section:

- `coords.rs` — NdSolve's doubled coordinate system (`Coords = [i8;4]`, cubie centers at `{-2,0,2}`, stickers additionally at `±4` on the axis they face), kept separate from `piece.rs`'s undoubled positions because it can name a single sticker. `Twist { face_axis, face_sign, from_axis, to_axis }` is one outer-side quarter turn (no `slices_mask`, unlike the Java original - every twist here turns a whole outer side); `twist90`/`twist90s` apply them to points, `make_signed_twist90` is Java's `makeTwist90`, `reverse_twists` its `reverseMoves`. Also the grid slot order (`slot_of`/`coords_of_slot`: base-5 digits, axis 0 most significant - Java's own iteration order, so cycles are found in the same order and the output matches Java twist for twist) and small vector helpers. Java's `while (!cond) axis++` searches become `find_axis(..)?`, returning `SolveError::Internal` instead of running off the array.
- `grid.rs` — `WantsGrid`, the port of `figureOutWhereIndicesWantToBe`: for every cubie center and sticker, where whatever sits there wants to go, built from a `Hypercube` (via `piece::side_for_kind`). Building it is also the input validation: exactly 81 pieces in canonical order, stickers exactly on a piece's nonzero axes, known kinds naming distinct axes, piece homes a bijection (`SolveError::Malformed`); a cell center carrying another side's kind is `Unsolvable::CellCenterMoved`.
- `rotation.rs` — `find_rotation_sequence` (the whole-puzzle rotation search every setup move is found with: make each axis column match up to sign with quarter turns, fix sign pairs with half turns, then one of three tricks for a last lone flipped column; `Ok(None)` for a mirror image when asked) and `find_oneface_twist_sequence` (the same with the face's own center pinned).
- `position.rs` — `position_ksticker_cubies` (cycle decomposition, `split_into_tricycles`), `cycle_3_ksticker_cubies`, `cycle_l_of_ksticker_cubies` (four half turns for 2-sticker pieces), `cycle_l_of_kslabs` (the 8-move 3D corner cycle on edge rows, plus one commutator layer for corners), `take_tricycle_to_l` (its two near-identical Java blocks share `bring_next_to`), `take_two_ksticker_cubies_to_i`.
- `orient.rs` — `orient_ksticker_cubies` (with `flip_pairs`/`twirl_pairs` regrouping sticker cycles, borrowing a solved "happy helper" piece when everything left is on one piece), `flip_two_noncorner_cubies`, `flip_two_canonical_kslabs` (the 3^4-specific two-edge flip), `flip_i_of_2sticker_cubies`, `twirl_two_corner_cubies`, `twirl_two_canonical_corner_kslabs`, `flatten_flip_pair_or_twirl_pair`. One deliberate fix: the Java happy-helper axis search tests an index-space value that's never 0, so it always rotates axes 0→1 and, for a piece zero on both, picks the very piece being fixed; `happy_helper_rot` tests coordinates as its comment intends.
- `solvable.rs` — `puzzle_state_is_odd`, `is_positioned_up_to`/`is_oriented_up_to` (without Java's per-type masks), `check_solvable` (port of `isSolvable`: mirrored corners, then per piece type after the parity twist, permutation parity, then flip parity or the corner twirl sum mod 3 via `intdet4`), each failure a distinct `Unsolvable` variant.
- `native.rs` — bridges `Twist` to native `moves::Move`. `twist_to_move` is the single ±90° move about the local axis not involved in the twist's `from`/`to` pair (proven against an independent doubled-coordinate oracle for all 48 twists, from solved and scrambled states). `merge_stage` composes consecutive same-side twists into one native move (90°/180° face, 180° edge, ±120° corner via `moves::native_move_for_rotation`) with a stack, dropping runs that cancel - sound across gaps too (`A B B' A'` → nothing) by associativity.
- `test_support.rs` (tests only) — shared contract-test helpers.

**Orchestration (`mod.rs`).** `solve` validates, returns an empty `Solution` for an already-solved cube, runs `check_solvable`, then `solve_raw`: the parity twist if needed, then position/orient for k = 2, 3, 4. Rather than porting Java's grid-twisting, each stage's twists are applied to a working `Hypercube` via `Hypercube::apply(twist_to_move(..))` and the grid rebuilt, so `moves.rs` stays the only definition of a move; the positioned/oriented invariants are checked after every stage (as errors, not asserts). Stages are merged separately, so every step's stage label is exact, and the merged moves are replayed on a clone - anything but `Hypercube::solved()` is `SolveError::Internal`, so a bug can surface as an error but never as a wrong solution. Branches only other puzzle sizes reach (2^d, 5+ dimensions, multi-slice twists: the "/" flip base case, the recursive flip step, the twirl-reversing "finalFinal" twist, the d≥5 helper fix-up) return `Internal` instead of being ported; Java's contract asserts are `debug_assert!`s.

**Tests.** Each primitive is contract-tested on a solved cube - it must move exactly the named pieces/stickers and leave every other piece with k or fewer stickers untouched: every 3-cycle of every piece type (~45k), every 2- and 3-sticker flip pair, every opposite-handed twirl pair. The default run samples them; the exhaustive sweeps are `#[ignore]`d (`cargo test --release solver -- --ignored`), as is a 5,000-scramble soak. End to end: 200 random scrambles solve, stages come out in order, output is deterministic, single odd moves start with the parity stage, and every kind of unsolvable/malformed input is an `Err`, never a panic.

**Measured** (release, 5,000 200-move scrambles): 1,734 raw quarter turns on average (max 2,378), merged to 1,214 native moves - about 49 s of playback at `shader_widget::SOLVE_MOVE_DURATION` - in 2.4 ms per solve.
