# menu_overlay.rs

The File/Puzzle/View/Help menu bar, built on `overlay::menu::Menu` (the same lower-level primitive `PickList`/`ComboBox` use internally). `MenuBar` is a hand-written `advanced::Widget<Message, iced::Theme, iced::Renderer>` (concrete renderer/theme, not generic, since this is app-specific code rather than a reusable library widget) modeled closely on `iced_widget::pick_list::PickList`'s own `Widget` impl: `layout()` places fixed-size button rects (no text measurement, unlike `PickList`); `draw()` fills each button's background/text directly via `Renderer::fill_quad`/`fill_text`; `update()` toggles open/closed state on left-click, following exactly the same pattern `PickList` uses to close on any click it receives while open (whether that click lands elsewhere on the bar or anywhere else in the window) - no backdrop/`mouse_area` needed, since the widget tree's own event routing already gives the base widget first refusal on any click the open dropdown's own `overlay::menu::Menu` doesn't consume.

`State` holds one `MenuState` (an `overlay::menu::State` plus `hovered_option`) per top-level menu as separate named fields (`file`/`puzzle`/`view`/`help`), not a `Vec` - this is what makes `overlay()`'s borrow-splitting work: borrowing `state.file.menu` and `state.view.menu` are visibly-disjoint field paths to the borrow checker in a way `state.menus[i]` wouldn't be. `open: Cell<Option<TopMenu>>` (not a plain field) is the one exception: `overlay()`'s `on_selected` closure needs to close the menu by mutating `open` while `menu_state`/`hovered` (borrowed from `state.file`/`.puzzle`/`.view`/`.help` via a `match` on which menu is open) are simultaneously alive - since which field is borrowed is a runtime choice, the disjoint-closure-capture trick `pick_list.rs` relies on for its own (always-the-same-fields) case doesn't apply here, so `open` uses interior mutability instead: `&state.open` (shared) is taken before the match borrows the other fields mutably, sidestepping the conflict entirely.
