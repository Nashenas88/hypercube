# shaders/*.wgsl

WGSL shaders sharing `Transform4D` (`rotation_matrix`, `viewer_distance`, `sticker_scale`, `face_gap`, `face_gap_4d`, `elapsed_seconds`), `CameraUniform`, and `StickerInstance` structs plus 4D math functions, all defined once in `math4d.wgsl` and pulled into each pipeline shader via `naga_oil`'s `#import` (composed in `renderer.rs` through a `naga_oil::compose::Composer`, since WGSL itself has no import mechanism). `sticker_common.wgsl` similarly shares `LightUniform`, `HighlightingUniform`, the `piece_slots` storage array, and the `sticker_order` storage array (and their bound globals) across every sticker material shader and the particle pipeline; its `@group(0) @binding` numbers are ordered by descending readership across the classic/elemental/particle pipelines rather than by which module owns the declaration. `classic_shader.wgsl` is the Classic theme's sticker material (flat per-`kind` colors from a `KindColors` uniform); `elemental_shader.wgsl` is the Elemental theme's, switching on `kind` to pick an animated material per element (helpers `hash11`/`hash21`/`value_noise1`/`fresnel`/`strobe` shared via `elemental_common.wgsl`, which also holds `LIGHTNING_STROBE_HZ` and `ICE_TWINKLE_HZ` so each element's material animation and its particles stay on one beat) and driven by `Transform4D.elapsed_seconds`. Fire is the exception to that switch: `fs_main` discards `kind == 3` and Fire is shaded instead by `fs_fire`, a second fragment entry point over the same `vs_main`, which `renderer.rs`'s `fire_pipeline` draws per sticker in a blended, depth-write-off pass. Nothing writes a fire cube's depth, so `fs_fire` discards its own back faces by their current `world_normal` rather than by `cull_mode` (which stays `None` everywhere, since `world_normal` - unlike index winding - is derived fresh from the instance's own basis and never goes stale mid-move). Both entry points route their result through `apply_highlight` so the hover tint stays identical across the two passes. `fs_fire` takes its view direction from `CameraUniform.eye_position` rather than the `normalize(-world_position)` the surface materials approximate with; that made `binding: 1` fragment-visible in `main_bind_group_layout`. `particle_shader.wgsl` draws the Elemental theme's billboarded particles: a per-`kind` count of camera-facing quads per sticker (`Theme::particles_per_kind`, renderer.rs), generated entirely in the vertex shader from `@builtin(vertex_index)`/`@builtin(instance_index)` with no vertex buffer and no stored particle state - `sticker_index` is looked up from `sticker_common::sticker_order`, an indirection buffer grouping instances into contiguous `(face_id, kind)` blocks so `renderer.rs` can issue one draw per visible face and populated kind at that kind's own budget. `vs_main` switches on `kind` to dispatch to one function per element (`ice_particle`, `fire_particle`, etc.), each returning a `ParticleSample` (world position, billboard size, color, alpha) for `vs_main` to place; every element but Fire is a thin wrapper building its own `ParticleStyle` and handing it to the shared `styled_particle`, which hashes `instance_index` against the current lifetime cycle for a particle's launch direction and age, so the whole system is a function of `elapsed_seconds` with all distances expressed in sticker radii. `math4d.wgsl`'s `compute_sticker_anchor` supplies the sticker's projected world center plus the three half-edge vectors of its projected cube; particle directions are drawn evenly over the unit sphere in that local frame and mapped through those edges, so travel distance and billboard size follow however the 4D projection has warped that particular sticker - unequally per axis, not by one shared scale.

`post_process.wgsl` holds the HDR bloom chain `renderer.rs`'s `composite()` runs after every other pipeline has drawn into the offscreen `scene_view`: `vs_fullscreen` (a fullscreen triangle from `@builtin(vertex_index)` alone) is shared by `fs_bright_pass` (thresholds `scene_view` into a half-res target), `fs_blur_h`/`fs_blur_v` (a separable 9-tap Gaussian blur, one pass per axis), and `fs_composite` (adds the blurred result back into `scene_view`, bilinearly upsampled for free by `textureSample` against a half-res source). The first three read the vertex shader's own `uv` output, resolution-independent by construction, since their render pass is never viewport-restricted; only `fs_composite`'s is (to `Renderer::bounds`, a sub-rectangle of a larger `scene_texture`), so it instead derives its UV from `@builtin(position)` divided by `scene_texture`'s full `textureDimensions`, giving the absolute address a renormalized 0..1 UV over just the visible sub-rectangle couldn't.
