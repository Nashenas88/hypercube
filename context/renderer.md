# renderer.rs

Owns all wgpu resources (buffers, pipelines for standard/normal/depth/debug/sky/post-process, textures). `render()` picks its sticker pipeline/bind group from `(current_render_mode, current_theme)`: `RenderMode::Standard` dispatches to `classic_pipeline` or `elemental_pipeline` depending on `Theme`, both sharing `main_bind_group_layout`/`main_bind_group`; `Normals`/`Depth` ignore the theme entirely. Under `(Standard, Elemental)` the same pass then appends `particle_pipeline` draws - one per visible 4D face and populated `kind`, each a sub-range of `particle_ranges[face_id][kind]` (billboard instances of 6 generated vertices each, no vertex or instance buffer) - additively blended with depth test on and depth write off, so particles are hidden by geometry in front of them, glow over geometry behind them, and need no back-to-front sort. Those ranges index into `sticker_order_buffer`, an indirection buffer of sticker indices grouped into contiguous `(face_id, kind)` blocks (`build_sticker_order`/`build_particle_instances`) and rebuilt by `update_sticker_instances` whenever `sticker_generation` changes, since a move can change which kind occupies which face; the vertex shader looks a particle's owning sticker up there instead of dividing its instance index by a shared per-kind budget, so each `kind` can carry its own particle count (`Theme::particles_per_kind`). It reuses `classic_pipeline_layout`/`main_bind_group` and simply leaves the bindings it doesn't read unused. Draws the 216 sticker facets per pipeline with up to 8 instanced draw calls, one per 4D `face_id`: each draws a 36-index winding-corrected chunk (`face_index_buffer`, computed by `calculate_indices`) against the matching 27-instance range. This depends on `FACET_TABLE` (`piece.rs`) being built in face-major blocks of 27 — see that table's doc comment. `render()` takes a `visible_faces: &[bool; 8]` (from `math::visible_faces`, `HypercubePrimitive`'s own field, computed in `shader_widget.rs`'s `draw()`) and skips the draw call entirely for any `face_id` it marks invisible — but only outside a move animation: `sticker_instances_for_render` can rotate a moving-layer facet's `face_normal_4d` away from its static `face_id`'s `FACE_CENTERS` direction mid-turn, so `draw()` falls back to "all visible" while `animating_move` is set and lets the vertex shader's own (unchanged) `is_face_visible` cull per-instance instead, same as before this optimization existed. `update_indices`/`update_sticker_instances` are generation-gated: `HypercubeShaderState` tags its cached index/instance buffers with a generation counter (bumped only when the underlying data actually changes — 4D rotation for indices, move animation/`Hypercube` state for instances), carried through `HypercubePrimitive`, so `Renderer` skips the `queue.write_buffer` GPU upload on frames where nothing changed (e.g. a plain 3D camera drag).

`render()` draws into `scene_view`, an offscreen `HDR_FORMAT` (`Rgba16Float`) target rather than iced's own surface - every pipeline above targets it, so a material can write emission past 1.0 without clipping at the display's 8-bit range. `composite()` (called separately, after `render()`) turns that into the final frame: under `Theme::Elemental` it runs `bright_pass_pipeline` (thresholds `scene_view` into half-res `bloom_view_a`) then `blur_h_pipeline`/`blur_v_pipeline` (a separable Gaussian blur ping-ponging `bloom_view_a`/`bloom_view_b`, leaving the result back in `bloom_view_a`); otherwise it clears `bloom_view_a` to black so a stale bloom from an earlier Elemental frame is never added in. Either way `composite_pipeline` then blits `scene_view` plus `bloom_view_a` into `target` (iced's surface), viewport-restricted to `self.bounds` same as `render()`'s own passes. All four post-process pipelines share `post_process.wgsl`'s `vs_fullscreen` (a fullscreen triangle from `@builtin(vertex_index)` alone, no vertex buffer) and read `@builtin(position)` directly for their UV, since only the composite pass's viewport is restricted - the others always cover their entire (freshly resize-tracked) target. `scene_texture`/`bloom_texture_a`/`bloom_texture_b` and their bind groups (`create_hdr_target`/`create_post_process_bind_groups`) are recreated in `resize()` alongside `depth_texture`, at the window's full size and half that respectively; nothing but `composite_pipeline`'s own output format depends on `format`, the real surface format passed into `Renderer::new` - every other pipeline, `debug_pipeline` (AABB) aside, targets `HDR_FORMAT` regardless. `render_debug_aabb()` draws directly onto `target` after `composite()`, so debug AABBs are excluded from bloom and need no HDR treatment.
